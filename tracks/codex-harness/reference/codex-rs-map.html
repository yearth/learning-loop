codex-rs 分层地图

openai/codex 仓库速查 · 口径 2026-08（main）· 137 个 workspace crate

药丸为代表性 crate（非全集，完整清单见 codex-rs/Cargo.toml）。高亮表示该组的"第一入口"。

入口层 FRONTENDS —— 把某种界面接进内核

同一个内核，五种进入方式：

cli → codex 主命令 tui → 终端交互界面 exec → codex-exec 非交互 app-server → JSON-RPC（App / IDE） mcp-server → 把 Codex 暴露为 MCP server（原型）

周边：app-server-transport / app-server-protocol / app-server-daemon / exec-server

内核层 KERNEL —— agent 的大脑

数量最少、体积最大的一层：

core —— agent loop · thread/session · context · 工具编排（最大 crate） protocol —— Op / EventMsg 词汇表 tools apply-patch —— 模型输出 → 文件补丁 prompts shell-command core-api / core-plugins

基础设施层 INFRASTRUCTURE —— 环绕大脑的器官

安全与策略 ≈ 8

决定"能不能做"：

sandboxing linux-sandbox bwrap（bubblewrap） execpolicy —— 审批策略引擎 process-hardening network-proxy shell-escalation secrets

记忆与状态 ≈ 6

会话持久化与恢复：

rollout —— 会话回放 / resume rollout-trace thread-store state history agent-graph-store

模型接入 ≈ 9

把"大脑"接到各种模型后端：

model-provider-info model-provider codex-api / codex-client backend-client responses-api-proxy ollama / lmstudio http-client

扩展生态 ≈ 20+

数量最大的一组——harness 的主体是环境工程：

skills plugin hooks connectors code-mode 家族 ×5 ext/ ×13（agent · mcp · skills · web-search · memories · goal · queue …）

云端与支撑 其余 ≈ 80

cloud-tasks / cloud-config（云端任务），login，以及大量 utils/*（路径、缓存、PTY、流解析……）
