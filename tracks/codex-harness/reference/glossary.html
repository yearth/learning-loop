codex-harness 术语表

中英对照速查 · 口径 2026-08-27（openai/codex main）· 随课程滚动增补

每条给一句话定义 + 仓库锚点。锚点是本地 checkout 中的位置，GitHub 上按 main 分支对号入座。分组即心智模型：循环是引擎，词汇表是边界上的合同，账本是持久化，安全分判定与执行两层。

① 循环与组织

crateRust 编译/打包单位
Rust 里一个目录一个 crate，是最小的可复用模块单位。codex-rs workspace 共 137 个。

workspacecodex-rs/Cargo.toml
共享依赖与构建配置的 crate 集合，整个 codex-rs 是一个 workspace。

agent loopcore
模型 → 工具调用 → 结果回流 → 再模型的循环，agent 的引擎。第 2 课主菜。

turnprotocol · "Submission operation"
一次用户提交（submission）到任务完成的周期。TurnContextItem "Persist once per real user turn"。

② 词汇表——协议家族

Opprotocol/src/protocol.rs:573
前端 → 内核的请求词（"Submission operation"）：Interrupt 打断、ExecApproval 审批答复、UserInputAnswer 追问答复、RealtimeConversation* 一族（实时语音）。

EventMsgprotocol/src/protocol.rs:1335
内核 → 前端的事件词（"Response event from the agent"）：Error、Warning 等。与 Op 构成一对请求/响应。

protocol（crate）codex-rs/protocol
进程内边界的词汇表。TUI 用它，app-server 内部也 submit(Op::…)——后者对外翻译 JSON-RPC、对内说 Op。

app-server-protocolcodex-rs/app-server-protocol/src/protocol/v2/
跨进程边界（App / IDE ↔ app-server）的 JSON-RPC 词汇，方法按 <resource>/<method> 命名：thread/read、thread/resume、thread/fork、thread/rollback。v2 是活跃版本。

MCPcodex-rs/mcp-server
Model Context Protocol，对接外部工具/资源生态的标准协议。mcp-server crate（官方自称 Prototype）还能把 Codex 自己暴露为 MCP server。

InterAgentCommunicationprotocol/src/protocol.rs:783
多 agent 之间的通信消息，同时也作为一种 RolloutItem 进账本——agent 间协作也在被誊录。

③ 账本——rollout 家族

rolloutcodex-rs/rollout · $CODEX_HOME/sessions/
会话逐笔展开的记录（JSONL，rollout-<时间戳>-<会话id>.jsonl）。取字面义"展开"，非"灰度发布"。首提交 2025-05-07 #845 "save session transcripts"；2026-03-24 #15548 抽成独立 crate。写入走异步队列，失败可重试，不阻塞前端。

RolloutItemhistory/src/lib.rs:96
账本条目，十种变体：SessionMeta / ResponseItem / InterAgentCommunication / Compacted / TurnContext / WorldState / SecurityRiskScore / EventMsg / RealtimeItem / 元数据变体。账本 ≠ 聊天记录。

Compactedhistory/src/lib.rs:147
上下文压缩事件：message（摘要）+ replacement_history（压缩后的替换历史）+ window 链（window_id / previous_window_id / first_window_id）——压缩是有谱系的窗口链，不是一次性摘要。resume 靠它还原"压缩后"的上下文视图。

WorldStateprotocol/src/protocol.rs:3109
世界状态 diff 基准（"resume model-visible world-state diffing"）：full=true 全量快照建基线，full=false 增量补丁更新基线。resume 后据此继续算"世界变了什么"。

SecurityRiskScoreprotocol/src/security_risk.rs:13
安全风险分类器的打分快照（scores + call_id + action）。注释明说"must not enter model-visible conversation context or user-visible thread item projections"——不给模型看、不给界面看的纯审计条目。

TurnContextprotocol/src/protocol.rs
每个真实用户轮次持久化一次（轮中压缩后再记一次），"so resume/fork replay can recover the latest durable baseline"。

RealtimeItemhistory/src/lib.rs:108
"Sparse, model-invisible facts used to reconstruct realtime presentation"——重建实时（语音）会话演示用的稀疏事实，模型不可见。

resumecli · codex resume
按账本把会话接回来的正式命令（另见 thread/resume、thread/rollback、thread/fork）。

CodexHarnessMetadatahistory/src/rollout_payload.rs:30
账本条目可携带的"harness 元数据"——仓库自己就用 harness 称呼这一层。

④ 安全——判定与执行

SandboxModeprotocol/src/config_types.rs:104
三档预设：read-only（默认）/ workspace-write / danger-full-access。

SandboxPolicyprotocol/src/protocol.rs:1049
更细粒度的沙箱策略，如 ReadOnly { network_access: bool }——read-only 档默认禁网。

sandboxing（crate）codex-rs/sandboxing/src/
执行层，按 OS 分家：seatbelt.rs（macOS）/ landlock.rs（Linux）/ bwrap.rs（bubblewrap）/ windows.rs，另有 violation（违规上报）、policy_transforms、manager。

.sbplsandboxing/src/*.sbpl
Seatbelt 策略文件格式，仓库里有四份：base / network / preferences / restricted_read_only_platform_defaults。

execpolicycodex-rs/execpolicy
判定层：命令级审批的规则引擎。输入待执行命令，输出 allow / prompt / forbidden。

prefix_ruleexecpolicy/README.md
execpolicy 的规则形态：pattern（有序 token，列表=可选）+ decision + justification + match/not_match（随规则自带、加载时验证的单元测试）。

Starlarkgithub.com/bazelbuild/starlark
execpolicy 的规则语言：Python 方言的配置语言，为 Bazel 而生。确定性（同输入同输出）、hermetic（摸不到文件/网络/时钟）、可嵌入——安全执行不可信代码的中间态。
