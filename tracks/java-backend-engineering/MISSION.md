# Mission: Java Backend Engineering

## Why

I am moving from frontend-focused delivery toward full-stack ownership. I want to understand and maintain real enterprise Java services without depending on AI to supply the causal model or decide whether an implementation is correct.

## Success looks like

- Trace an authorized request from the user interaction through the Java service to its actual data source and back.
- Explain the responsibilities and data transformations at the HTTP, application, domain, persistence, and service-integration boundaries.
- Distinguish confirmed code facts, inference, and unknowns, then identify the evidence required to resolve an unknown.
- Predict and explain transport success, business failure, downstream failure, timeout, and partial-success behavior.
- Complete a small, legitimate Java backend change and verify it with proportionate tests and runtime evidence.
- Review AI-generated Java changes for missed layers, unsafe failure handling, and unsupported assumptions.
- Turn private practice into public, transferable learning material without exposing private implementation details.

## Constraints

- Learn primarily from authorized real-world Java projects; no artificial application is maintained solely to simulate experience.
- Inspect production-project source read-only by default. Real changes require a genuine task and separate authorization.
- Start with one narrow read path before moving to writes, transactions, asynchronous processing, retries, and concurrency.
- Introduce Java language and JVM details when they become necessary to explain observed behavior.
- Keep the public repository free of private code, identifiers, data, documentation, paths, logs, and reconstructable system details.
- Prefer retrieval, prediction, and evidence-backed explanation over passive reading or interview-answer memorization.

## Out of scope

- Go learning until the Java backend foundation is stable enough to transfer.
- Production writes, data queries, or operational actions performed only for practice.
- Broad Java certification coverage or framework trivia without a connection to the mission.
- Publishing internal architecture, source evidence, or sanitized replicas of private systems.
