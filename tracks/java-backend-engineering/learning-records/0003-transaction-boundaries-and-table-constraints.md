# 记录 0003：事务边界、未知状态与建表约束

学习阶段：2026-09-08 后半段至 2026-09-14；承接记录 0002。证据为教学问答与隔日检索，不包含编码、数据库实验或生产故障复现。以下只记录通用概念与能力边界。

## 已在问答中独立表达

- 事务方法内部捕获异常并返回 false，外层代理接收到的是正常返回；在没有其他回滚标记的题设下，不会因这个布尔值自动回滚。
- 前端失败提示与数据库是否回滚需要分别确认。未知状态不能被抹成“无数据”或“无权限”，否则技术故障会被误报为业务事实。
- 响应丢失时，调用方无法据此确定写入结果；同一次提交需要保留并检查稳定请求标识。
- 数据仓库暂时查不到新记录，不能直接判定业务提交失败；同步延迟是待验证假设。
- 主键限制重复值。以申请人作为“一行一张申请”的表的主键，会阻止同一人创建第二张申请。
- 单据主键不会自动保证请求编号唯一；全表请求编号唯一可能误伤不同企业的合法同名编号。
- 并发下仅“先查不存在，再插入”不足以防重；重复请求应尝试返回原操作结果。具体并发时序和参数一致性条件经讲解补齐。

## 经讲解修正，仍需独立检索

- 注解提供配置，事务拦截器执行提交与回滚。catch 在事务边界内外的位置，会改变异常是否到达拦截器。
- 同对象内部调用不触发新的代理拦截，但数据库操作仍可能参与外层已开启的事务。两道题都经过外层代理时，不能把结果差异归因于 this 调用。
- 报错日志只是候选线索：需要关联同一次请求、定位调用阶段，并验证错误如何影响最终响应。即使追踪标识一致，错误也可能被重试恢复。
- 前端内存锁、执行期间的互斥锁、业务内容查重与持久化幂等记录保护的范围不同；不能由“有防重措施”直接推导端到端幂等保证，也不能由证据缺失直接断言线上会重复。
- 联合唯一约束要求组合不重复，各列不必单独唯一。幂等键涉及的列应明确非空要求与唯一范围。
- 唯一约束在并发插入时守住规则；冲突请求可能等待另一事务的提交或回滚。返回原结果前，应核实冲突约束、访问范围及关键参数一致性。
